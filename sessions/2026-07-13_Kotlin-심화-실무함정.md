## 질문 / 결론 / 근거

### Q1. `!!` 연산자는 언제 써도 괜찮은가?

결론: "이 값이 null이면 프로그래밍 버그다"가 확실한 경우에만. 그 외엔 `?:` + 의미있는 예외.
- 근거: `!!`는 NullPointerException을 그대로 던짐 — Kotlin에서 NPE를 보는 가장 흔한 원인
- 상태: ✅ 확정 (공식 문서)

### Q2. var 필드에 스마트 캐스트가 안 되는 이유는?

결론: 컴파일러가 null 체크와 사용 사이에 다른 스레드가 값을 바꿀 수 있다고 판단.
- 근거: Kotlin spec — val(로컬 변수)은 스마트 캐스트 가능, var/mutable property는 불가
- 해결책: 로컬 val에 캡처하거나 `?.let` 사용
- 상태: ✅ 확정

### Q3. @Transactional + suspend — 왜 동작 안 하는가?

결론: Spring @Transactional은 ThreadLocal 기반. suspend/resume 시 스레드가 바뀌면 ThreadLocal 컨텍스트가 끊어짐.
- 근거: Spring Framework docs, GitHub Issue #28290
- 해결책: `TransactionalOperator.executeAndAwait` (R2DBC) 또는 blocking 레이어 분리
- 상태: ✅ 확정

### Q4. Dispatchers.IO + @Transactional 조합이 커넥션 누수를 일으키는가?

결론: 그렇다. 트랜잭션 컨텍스트(ThreadLocal)에서 다른 Dispatcher로 전환하면 원래 커넥션이 반환 안 됨.
- 근거: 2차 출처 (Medium 아티클) — 단, Spring 내부 코드로 추가 검증 권장
- 상태: ⚠️ 2차 출처만 확인 — Spring 소스코드로 검증 권장

### Q5. GlobalScope는 왜 피해야 하는가?

결론: 앱 전체 생명주기에 묶임 → 취소 불가, 예외 핸들러 없음, 코루틴 누수.
- 근거: Roman Elizarov (코루틴 설계자) 블로그, Kotlin 1.5부터 @DelicateCoroutinesApi
- 상태: ✅ 확정

### Q6. Kotlin final class + Spring AOP 문제는 어떻게 해결하는가?

결론: kotlin-spring (all-open) 컴파일러 플러그인 사용. @Service, @Transactional 등에 자동으로 `open` 적용.
- 근거: Spring Kotlin 공식 문서
- 상태: ✅ 확정

### Q7. Jackson이 Kotlin data class를 역직렬화 못하는 이유는?

결론: Jackson 기본 동작이 no-arg 생성자 기반이고, data class는 기본 생성자 없음.
- 근거: jackson-module-kotlin 공식 문서
- 해결책: `jackson-module-kotlin` 의존성 + `registerKotlinModule()` (Spring Boot는 자동)
- 상태: ✅ 확정
