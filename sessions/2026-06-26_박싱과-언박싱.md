# 2026-06-26 세션: 박싱과 언박싱

## 질문

박싱과 언박싱

## 결론

- `Integer`는 `-128~127`만 내부 캐시로 동일 객체를 재사용한다 → `==` 비교 금지, `equals()` 사용.
- 언박싱 대상이 `null`이면 NPE가 난다 — `Map.get()` + 산술 연산, 삼항 연산자 타입 프로모션(피연산자가 `int`+`Integer` 혼합일 때) 두 케이스 모두 확인.
- Wrapper 누적 변수(`Long sum` 등)는 반복마다 박싱/언박싱 + 힙 할당이 발생해 GC 압박으로 이어진다. 누적 변수는 primitive를 쓴다.
- `List<Integer>`는 참조 배열 + 흩어진 객체(2단계 인다이렉션)라 `int[]`(연속 메모리) 대비 캐시 locality가 나쁘고 원소당 메모리 오버헤드가 붙는다.
