# 2026-06-26 세션: 클래스 로딩

## 질문

JVM 클래스 로딩 — 부모 위임 모델, 클래스 동일성, Linking 단계, Initialization 트리거

## 결론

- 클래스로더는 Bootstrap → Platform → Application 3단계 계층이며, 클래스를 찾을 때 항상 부모에게 먼저 위임한다 (`java.lang.ClassLoader`의 기본 구현 동작, JVMS가 강제하는 규칙은 아님).
- JVM에서 클래스 동일성은 이름이 아니라 (binary name, defining loader) 쌍으로 결정된다. 같은 바이트코드를 다른 로더가 로드하면 별개의 `Class` 객체가 되어 `==`/`instanceof`/캐스팅이 모두 다르게 동작한다.
- Linking은 Verification(구조 검증) → Preparation(static 필드 기본값 할당, 바이트코드 실행 없음) → Resolution(심볼릭 참조 해석, lazy/eager 가능) 순서다.
- 클래스 초기화(Initialization)는 인스턴스 생성/static 메서드 호출/static 필드 대입/상수 아닌 static 필드 사용 중 하나가 처음 일어나기 전에 트리거된다. `static final` 컴파일 시점 상수는 호출자 바이트코드에 인라인되어 트리거에서 빠진다.
