# 2026-06-26 세션: 가비지 컬렉션 (GC)

## 질문

JVM GC — 회수 판단 기준, Young/Old 분리 이유, Minor GC vs Full GC와 STW 발생 원인

## 결론

- GC의 회수 기준은 참조 카운트가 아니라 **reachability(도달 가능성)** 다. GC Root에서 추적 불가능한 객체가 회수 대상이며, HotSpot은 tracing GC를 쓴다.
- Young/Old 분리의 근거는 "오래 참조시키기 위해서"가 아니라 **weak generational hypothesis(대부분 객체가 짧게 산다)** 다. 이 경험적 사실 때문에 Young만 자주 싸게 비우는 전략이 성립한다.
- Minor GC는 Young만, Major(Full) GC는 Old(또는 전체 Heap)를 정리한다. 단 "Major"/"Full" 용어는 컬렉터/문서마다 정의가 달라 단정하지 않음.
- STW는 단순 "스레드 점유"가 아니라, GC가 객체 그래프를 순회·이동하는 동안 참조 관계의 일관된 스냅샷이 필요해서 발생한다. concurrent 컬렉터도 일부 단계(initial-mark/remark)는 STW다.

## 모르는 것 / 후속 과제

- "Major GC"와 "Full GC" 용어가 컬렉터별로 정확히 어떻게 구분되는지 — 직접 확인 안 됨.
- safepoint 진입/탈출 메커니즘의 구체적 구현 (poll 방식, 시그널 방식 등) — 직접 확인 안 됨.
- G1/ZGC 등 구체 알고리즘별 STW 단계 차이 — 다음 세션에서 이어서 진행 가능.
