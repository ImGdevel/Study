# 박싱과 언박싱

> 태그: `#java` `#primitive` `#wrapper`<br>
> 작성일: 2026-06-26<br>
> 최종 수정일: 2026-06-26

## 정의

오토박싱은 primitive 값을 대응하는 Wrapper 객체로, 언박싱은 Wrapper 객체를 대응 primitive 값으로 컴파일러가 자동 변환하는 것이다.

## 특징 / 상세

### Integer 캐시와 `==` 함정

`Integer.valueOf(int)`는 `-128~127` 범위를 내부 캐시(`IntegerCache`)에 미리 만들어두고 재사용한다. 이 범위 밖의 값은 매번 `new Integer(...)`로 새 객체를 만든다.

```java
Integer a = 100, b = 100;   // valueOf(100) → 캐시 적중, 같은 참조 → a == b 는 true
Integer a2 = 200, b2 = 200; // valueOf(200) → 캐시 미스, 매번 new → a2 == b2 는 false
```

`-128~127`이 캐시 범위인 이유는 [JLS §5.1.7 Boxing Conversion](https://docs.oracle.com/javase/specs/jls/se21/html/jls-5.html#jls-5.1.7)이 이 범위는 박싱 시 항상 동일 객체를 반환하도록 강제하기 때문이다. HotSpot 구현(`java.lang.Integer.IntegerCache`)은 `-XX:AutoBoxCacheMax=<size>` 옵션으로 상한을 늘릴 수 있지만, 스펙이 보장하는 범위는 `-128~127`뿐이다.

**`Integer`는 `==`로 비교하지 않는다. `equals()`를 쓴다.**

### 언박싱 중 NPE — 케이스 1: Map.get() + 산술 연산

```java
Map<String, Integer> counts = new HashMap<>();
int c = counts.get("x") + 1;
```

`counts.get("x")`가 키가 없어 `null`을 반환하면, 컴파일러가 삽입한 `counts.get("x").intValue() + 1` 코드에서 `.intValue()` 호출 시점에 `NullPointerException`이 발생한다. `Integer + 1` 자체는 문제 없다 (언박싱 후 `int` 산술) — 문제는 언박싱 대상이 `null`일 수 있다는 점을 놓치는 것이다.

### 언박싱 중 NPE — 케이스 2: 삼항 연산자 타입 프로모션

```java
Integer a = null;
int b = 5;
Object result = true ? a : b;
```

대입 대상이 `Object`라서 박싱/언박싱이 안 일어날 것 같지만, 조건식의 타입은 대입 대상이 아니라 두 피연산자(`a`, `b`)의 타입으로 결정된다. 한쪽이 primitive `int`이고 다른 쪽이 그 박싱 타입(`Integer`)이면 [JLS §15.25.2 Numeric Conditional Expressions](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.25.2)에 따라 조건식 전체 타입이 `int`로 고정되고, 선택된 피연산자가 `int`로 언박싱된다. 조건이 `true`라 `a`가 선택되지만, `a`가 `null`이라 언박싱 시점에 NPE가 난다.

검증 상태: JLS 5.1.7과 OpenJDK `IntegerCache` 소스는 원문 직접 확인함. JLS 15.25.2는 절 존재만 확인했고 본문 전문은 직접 열어서 재확인을 권장한다.

### 루프 내 박싱/언박싱 오버헤드

```java
Long sum = 0L;
for (long i = 0; i < N; i++) {
    sum += i; // sum.longValue() 언박싱 → long 덧셈 → Long.valueOf(결과) 박싱(매번 new, 캐시 범위 밖)
}
```

매 반복마다 언박싱 + 박싱(새 객체 할당)이 일어난다. 단순 CPU 오버헤드가 아니라 매 반복 힙 할당이 발생해 GC 압박으로 이어진다. **누적 변수는 `Long` 대신 `long` primitive를 써야 한다** — 박싱/언박싱 자체를 제거해서 할당이 0이 된다.

### List<Integer> vs int[] 메모리 구조

`int[]`는 배열(힙 객체) 내부에 원소가 연속(contiguous)으로 저장된다 — 헤더 + length + `int` 값들이 한 블록. 순회 시 캐시 locality가 좋다.

`List<Integer>`(`ArrayList` 내부는 `Object[]`)는 두 단계 인다이렉션이다. 배열엔 참조만 연속으로 들어있고, 그 참조가 가리키는 `Integer` 객체는 각각 별도로 힙에 흩어져 있다 (`-128~127` 캐시 범위 값은 같은 객체를 재사용하지만 그 밖은 매번 새 위치). 원소당 객체 헤더+패딩 오버헤드가 추가로 붙고, 순회 시 캐시 미스가 잦다. 정확한 바이트 수는 JVM/compressed-oops 설정에 따라 다르므로 필요하면 [JOL](https://github.com/openjdk/jol)로 직접 측정한다.
